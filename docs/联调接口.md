# 图片智能处理服务 · URL 联调接口

> 版本：2026-08-31
> 本文档是客户联调的当前有效线协议。图片通过 URL 提交，不要求客户上传文件。

## 1. 对接流程

```text
客户服务                                 图片智能处理服务
   │                                             │
   │── POST JSON（objectKey + imageUrl）────────▶│
   │◀── 201（job_id + taskId）───────────────────│
   │                                             │ 异步下载、筛选、美化、打标
   │◀── POST notifyUrl（results）────────────────│
   │── HTTP 2xx ────────────────────────────────▶│
```

## 2. 基础信息

| 项目 | 说明 |
|---|---|
| 联调 Base URL | `http://47.111.188.85:18081` |
| 创建任务主路径 | `/api/v1/integration/jobs` |
| 客户原路径兼容 | `/api/app/image/filter-requests` |
| 鉴权请求头 | `X-API-Key: <双方约定的密钥>` |
| 请求格式 | `application/json` |
| 支持图片 | JPEG、PNG、WebP |
| 单张限制 | 25 MB |
| 单任务限制 | 1～50 张，`objectKey` 不得重复 |

## 3. 创建任务

### 3.1 请求

```http
POST /api/v1/integration/jobs
Content-Type: application/json
X-API-Key: <API_KEY>
```

```json
{
  "notifyUrl": "https://client.example.com/v1/callback/ai/theme-image/notify",
  "images": [
    {
      "objectKey": "img/2026/08/abc123.jpg",
      "imageUrl": "https://obs.example.com/img/2026/08/abc123.jpg"
    },
    {
      "objectKey": "img/2026/08/def456.jpg",
      "imageUrl": "https://obs.example.com/img/2026/08/def456.jpg"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `notifyUrl` | String | 是 | 任务终态回调地址，支持 HTTP/HTTPS；正式公网建议使用 HTTPS |
| `images` | Array | 是 | 待处理图片，1～50 张 |
| `images[].objectKey` | String | 是 | 客户图片唯一键，最长 200；回调原样返回 |
| `images[].imageUrl` | String | 是 | 服务端可直接下载的 HTTP/HTTPS 图片地址 |

客户不需要传过滤、美化或模型配置，图片服务使用已配置的正式处理标准。

`imageUrl` 要求：

- 图片服务所在网络能够访问；
- 无需登录、Cookie 或二次鉴权；
- 如果使用签名 URL，有效期必须覆盖任务创建阶段；
- 不允许指向本机、内网、回环或云元数据地址；
- 服务端会校验响应类型和下载后的实际图片内容。

同时兼容 snake_case 字段：`callback_url`、`object_key`、`image_url`。

### 3.2 curl 示例

```bash
curl -X POST "http://47.111.188.85:18081/api/v1/integration/jobs" \
  -H "X-API-Key: <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "notifyUrl":"https://client.example.com/v1/callback/ai/theme-image/notify",
    "images":[
      {
        "objectKey":"img/2026/08/abc123.jpg",
        "imageUrl":"https://obs.example.com/img/2026/08/abc123.jpg"
      }
    ]
  }'
```

### 3.3 成功响应

HTTP 状态码：`201 Created`

```json
{
  "job_id": "job_ab1bdc6b2c14480886243bb3e4e25580",
  "status": "queued",
  "total": 1,
  "ok": true,
  "code": "",
  "message": "",
  "taskId": "job_ab1bdc6b2c14480886243bb3e4e25580"
}
```

`job_id` 与 `taskId` 是同一个任务编号，同时输出是为了兼容双方现有字段。客户收到 HTTP 201、`ok=true` 且 `taskId` 非空才表示受理成功。

### 3.4 错误响应

```json
{
  "detail": "错误原因"
}
```

| HTTP 状态码 | 含义 |
|---|---|
| `400` | 图片 URL 无法下载、类型/大小不合法、回调地址或业务配置不合法 |
| `401` | `X-API-Key` 缺失或错误 |
| `413` | 请求体超过网关限制 |
| `415` | `Content-Type` 不是 JSON 或兼容的 multipart |
| `422` | JSON 缺字段、类型错误、`objectKey` 重复或 URL 格式错误 |
| `429` | 请求过于频繁 |
| `500` | 服务内部错误 |
| `503` | 服务依赖或鉴权配置未就绪 |

## 4. 结果回调

任务进入 `completed`、`partial_failed`、`failed` 或 `cancelled` 后，图片服务向本次请求的 `notifyUrl` 发送：

```http
POST {notifyUrl}
Content-Type: application/json; charset=utf-8
X-Callback-Event: image.job.finished
X-Callback-Id: <回调幂等编号>
X-Callback-Timestamp: <Unix 秒时间戳>
X-Callback-Signature: sha256=<HMAC-SHA256>
```

```json
{
  "results": [
    {
      "objectKey": "img/2026/08/abc123.jpg",
      "decision": "selected",
      "score": 86.5,
      "enhancedUrl": "https://image-service.example.com/result/abc123.jpg",
      "enhancedMd5": null,
      "aiTags": ["客厅", "采光好"]
    },
    {
      "objectKey": "img/2026/08/def456.jpg",
      "decision": "rejected",
      "score": 42.0,
      "enhancedUrl": null,
      "enhancedMd5": null,
      "aiTags": []
    }
  ],
  "errorMessage": ""
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `results[].objectKey` | String | 创建任务时传入的值，原样返回 |
| `results[].decision` | String | `selected`、`rejected`、`not_selected`、`failed` 或 `cancelled` |
| `results[].score` | Number/null | 综合质量评分，0～100 |
| `results[].enhancedUrl` | String/null | 美化图临时下载地址，仅有产出时返回 |
| `results[].enhancedMd5` | String/null | 当前可能为空，客户不得作为必填字段 |
| `results[].aiTags` | String[] | AI/素材库标签列表 |
| `errorMessage` | String | 任务级错误；成功时为空字符串 |

客户成功保存回调后返回任意 HTTP 2xx，例如：

```json
{"code":"200","msg":"success","data":{}}
```

非 2xx、连接失败或 15 秒超时会自动重试，默认最多 5 次。客户应优先使用 `X-Callback-Id` 做幂等处理。

## 5. 补偿查询

```http
GET /api/v1/integration/jobs/{job_id}
X-API-Key: <API_KEY>
```

```http
GET /api/v1/integration/jobs/{job_id}/results?limit=50&offset=0
X-API-Key: <API_KEY>
```

正常业务以回调为准，查询接口只用于排障和补偿。

## 6. 兼容说明

- `/api/v1/integration/jobs` 当前同时接受 URL JSON 和历史 multipart 请求；
- 历史文件上传也可以使用 `/api/v1/integration/file-jobs`；
- 客户原路径 `/api/app/image/filter-requests` 接受相同 URL JSON；
- 不再要求客户通过 `job_id` 猜测图片归属，回调会原样返回 `objectKey`；
- 密钥只通过安全渠道传递，不写入本文档。

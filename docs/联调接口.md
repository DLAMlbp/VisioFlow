# 图片智能处理服务 · 客户接口联调文档

> 文档版本：2026-08-31
>
> 接口协议：`customer_v1`
>
> 适用范围：客户业务服务与图片智能处理服务之间的服务端对接
>
> 当前有效协议：URL 图片 + JSON 请求 + 异步结果回调

## 1. 对接结论

客户只需要提交：

- 结果回调地址 `notifyUrl`；
- 每张图片的客户侧唯一键 `objectKey`；
- 图片服务可直接下载的公网地址 `imageUrl`。

客户**不需要**提交 `filter_profile`、`beautify_profile`、完工分类标准或模型配置。过滤、美化及分类标准由图片服务统一配置和管理。

```text
客户业务服务                                  图片智能处理服务
     │                                                │
     │── POST JSON（objectKey + imageUrl）───────────▶│
     │◀── 201（job_id + taskId）──────────────────────│
     │                                                │ 异步下载、筛选、美化、匹配
     │◀── POST notifyUrl（完整 results）──────────────│
     │── HTTP 2xx ───────────────────────────────────▶│
```

## 2. 基础信息

| 项目 | 当前联调配置 |
|---|---|
| Base URL | `http://47.111.188.85:8088` |
| 创建任务 | `POST /api/v1/integration/jobs` |
| 兼容创建路径 | `POST /api/app/image/filter-requests` |
| 查询进度 | `GET /api/v1/integration/jobs/{job_id}` |
| 查询结果 | `GET /api/v1/integration/jobs/{job_id}/results` |
| 鉴权请求头 | `X-API-Key: <双方约定的集成密钥>` |
| 创建请求格式 | `application/json` |
| 回调请求格式 | `application/json; charset=utf-8` |
| 支持图片 | JPEG、PNG、WebP |
| 单张图片上限 | 25 MB |
| 单任务图片数 | 1～50 张 |
| 图片 URL 下载超时 | 20 秒 |
| 回调超时 | 15 秒 |
| 回调最大投递次数 | 5 次 |

安全要求：

- `X-API-Key` 只允许保存在客户服务端，不得放入网页、App、小程序或公开代码仓库；
- API Key 和回调签名密钥通过双方约定的安全渠道单独提供，不写入本文档；
- 当前联调地址为 HTTP，正式公网环境建议切换到 HTTPS。

## 3. 创建图片处理任务

### 3.1 请求定义

```http
POST /api/v1/integration/jobs HTTP/1.1
Host: 47.111.188.85:8088
X-API-Key: <API_KEY>
Content-Type: application/json
```

### 3.2 请求报文

```json
{
  "notifyUrl": "https://client.example.com/v1/callback/ai/theme-image/notify",
  "images": [
    {
      "objectKey": "img/2026/08/abc123.jpg",
      "imageUrl": "https://obs.example.com/img/2026/08/abc123.jpg"
    },
    {
      "objectKey": "img/2026/08/def456.jpg",
      "imageUrl": "https://obs.example.com/img/2026/08/def456.jpg"
    }
  ]
}
```

### 3.3 请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `notifyUrl` | String | 是 | 本次任务的终态回调地址，必须是图片服务可访问的 HTTP/HTTPS 绝对地址 |
| `images` | Array | 是 | 待处理图片集合，1～50 张 |
| `images[].objectKey` | String | 是 | 客户侧图片唯一键，长度 1～200；同一任务内不得重复；回调时原样返回 |
| `images[].imageUrl` | String | 是 | 图片服务可以直接下载的 HTTP/HTTPS 公网地址 |

同时兼容以下 snake_case 字段：

| 推荐字段 | 兼容字段 |
|---|---|
| `notifyUrl` | `callback_url` 或 `notify_url` |
| `objectKey` | `object_key` |
| `imageUrl` | `image_url` |

建议客户统一使用本文档示例中的 camelCase 字段。

### 3.4 `imageUrl` 要求

- 图片服务所在网络必须能够直接访问；
- 不得依赖登录状态、Cookie、自定义请求头或二次鉴权；
- 如果使用签名 URL，有效期必须覆盖任务提交和服务端下载阶段；
- URL 不得包含用户名或密码；
- 不允许指向 localhost、内网 IP、回环地址、链路本地地址或云元数据地址；
- 重定向后的最终地址也必须满足以上安全要求；
- 响应内容必须是 JPEG、PNG 或 WebP，单张不超过 25 MB。

只要任意一张图片下载或校验失败，本次创建请求即失败，不会创建部分任务。

### 3.5 服务端默认处理标准

以下字段由图片服务管理，客户请求中不要提交：

- `filter_profile`；
- `beautify_profile`；
- `completion_profile`；
- `completed_filter_profile`；
- `non_completed_filter_profile`；
- `similarity_profile` 及模型配置。

服务端会自动完成图片完工状态识别、分支过滤、自然美化和素材匹配。服务端标准调整时，客户接口报文无需变化。

### 3.6 curl 示例

```bash
curl -X POST "http://47.111.188.85:8088/api/v1/integration/jobs" \
  -H "X-API-Key: <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "notifyUrl": "https://client.example.com/v1/callback/ai/theme-image/notify",
    "images": [
      {
        "objectKey": "img/2026/08/abc123.jpg",
        "imageUrl": "https://obs.example.com/img/2026/08/abc123.jpg"
      }
    ]
  }'
```

### 3.7 成功响应

HTTP 状态码：`201 Created`

```json
{
  "job_id": "job_ab1bdc6b2c14480886243bb3e4e25580",
  "status": "queued",
  "total": 1,
  "ok": true,
  "code": "",
  "message": "",
  "taskId": "job_ab1bdc6b2c14480886243bb3e4e25580"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `job_id` | String | 图片服务任务编号，客户应保存，用于补偿查询和排障 |
| `taskId` | String | 与 `job_id` 相同，用于兼容客户现有字段 |
| `status` | String | 创建成功时通常为 `queued` |
| `total` | Integer | 本任务包含的图片数量 |
| `ok` | Boolean | `true` 表示请求已受理 |
| `code` | String | 成功时为空字符串 |
| `message` | String | 成功时为空字符串 |

只有同时满足以下条件才表示任务受理成功：

- HTTP 状态码为 `201`；
- `ok` 为 `true`；
- `taskId`/`job_id` 非空。

创建接口目前不提供请求幂等键。客户超时重试前应先核对原请求是否已收到 `201`，并避免重复提交同一批业务图片。

### 3.8 失败响应

```json
{
  "detail": "错误原因"
}
```

| HTTP 状态码 | 含义 | 客户处理建议 |
|---|---|---|
| `400` | 图片 URL 下载失败、图片类型/大小不合法或业务配置校验失败 | 根据 `detail` 修正后重新提交 |
| `401` | `X-API-Key` 缺失或错误 | 检查集成密钥配置，不要无限重试 |
| `413` | 请求体超过网关限制 | 缩小请求体；URL JSON 不应携带图片二进制 |
| `415` | `Content-Type` 不受支持 | 改为 `application/json` |
| `422` | 缺少必填字段、字段类型错误、URL 格式错误或 `objectKey` 重复 | 根据 `detail` 修正请求 |
| `429` | 请求过于频繁 | 指数退避后有限重试 |
| `500` | 图片服务内部错误 | 保存 `X-Request-ID` 并联系服务方排查 |
| `503` | 服务依赖或集成鉴权配置未就绪 | 稍后重试或联系服务方 |

响应头中的 `X-Request-ID` 是本次请求的排障编号。客户反馈问题时，请同时提供请求时间、`X-Request-ID` 和 `job_id`（如果已生成），不要提供完整 API Key。

## 4. 结果回调

任务进入终态后，图片服务向本次请求的 `notifyUrl` 投递完整结果。客户正常业务应以回调为准。

### 4.1 回调请求头

```http
POST {notifyUrl} HTTP/1.1
Content-Type: application/json; charset=utf-8
User-Agent: image-intelligence-service/1.0
X-Callback-Event: image.job.finished
X-Callback-Id: <回调幂等编号>
X-Callback-Timestamp: <Unix 秒时间戳>
X-Callback-Signature: sha256=<HMAC-SHA256 十六进制摘要>
```

说明：

- `X-Callback-Id` 是回调幂等键，同一回调重试时保持不变；
- 回调不会携带创建任务时使用的 `X-API-Key`；
- 客户应使用双方单独约定的回调签名密钥校验 `X-Callback-Signature`；
- 客户应校验时间戳，并拒绝明显过期的请求，建议允许不超过 5 分钟的时钟偏差。

签名原文为：

```text
X-Callback-Timestamp + "." + 原始 HTTP 请求体字节
```

签名算法：

```text
hex(HMAC-SHA256(callback_secret, timestamp + "." + raw_body))
```

最终请求头值：

```text
sha256=<十六进制摘要>
```

必须使用接收到的原始请求体字节计算签名，不能先解析 JSON 再重新序列化。

### 4.2 回调报文

```json
{
  "results": [
    {
      "objectKey": "img/2026/08/abc123.jpg",
      "decision": "selected",
      "score": 86.5,
      "enhancedUrl": "https://download.example.com/enhanced/xxx.jpg?X-Amz-Expires=900&...",
      "enhancedMd5": null,
      "aiTags": ["客厅", "采光好"]
    },
    {
      "objectKey": "img/2026/08/def456.jpg",
      "decision": "rejected",
      "score": 42.0,
      "enhancedUrl": null,
      "enhancedMd5": null,
      "aiTags": []
    }
  ],
  "errorMessage": ""
}
```

### 4.3 回调字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `results` | Array | 本任务的单图处理结果集合 |
| `results[].objectKey` | String | 创建任务时客户传入的 `objectKey`，原样返回 |
| `results[].decision` | String | `selected`、`rejected`、`not_selected`、`failed` 或 `cancelled` |
| `results[].score` | Number/null | 综合质量评分，通常为 0～100；无可用评分时为 `null` |
| `results[].enhancedUrl` | String/null | 美化图临时下载地址；没有美化产出时为 `null` |
| `results[].enhancedMd5` | String/null | 当前版本可能为 `null`，客户不得将其作为必填值 |
| `results[].aiTags` | String[] | 图片标签数组；无标签时为空数组 |
| `errorMessage` | String | 任务成功时为空字符串；失败、部分失败或取消时返回任务级说明 |

`decision` 含义：

| 值 | 含义 |
|---|---|
| `selected` | 图片符合要求并被保留 |
| `rejected` | 图片不符合过滤标准 |
| `not_selected` | 图片合格，但未进入最终优选数量 |
| `failed` | 单图处理失败 |
| `cancelled` | 单图处理被取消 |

`enhancedUrl` 是临时签名地址，当前默认有效期为 900 秒。客户收到回调后应尽快下载并保存，不应长期保存该 URL 本身。

### 4.4 客户回调响应

客户成功校验并保存回调后，应在 15 秒内返回任意 HTTP 2xx。例如：

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "code": "200",
  "msg": "success",
  "data": {}
}
```

图片服务只判断 HTTP 状态码，不解析客户响应体。

- 非 2xx、连接失败或 15 秒超时会触发自动重试；
- 默认最多投递 5 次；
- 重试采用指数退避；
- 回调属于“至少一次投递”，客户必须按 `X-Callback-Id` 实现幂等；
- 建议客户先完成验签、幂等判断和持久化，立即返回 2xx，再异步下载结果图片。

## 5. 补偿查询

补偿查询使用创建任务时返回的 `job_id`，同样需要携带 `X-API-Key`。

### 5.1 查询任务进度

```http
GET /api/v1/integration/jobs/{job_id}
X-API-Key: <API_KEY>
```

示例响应：

```json
{
  "job_id": "job_ab1bdc6b2c14480886243bb3e4e25580",
  "status": "processing",
  "progress": 60,
  "total": 10,
  "processed": 6,
  "selected": 3,
  "rejected": 2,
  "not_selected": 1,
  "tagging": 2,
  "stage_counts": {
    "processing": 4,
    "selected": 3,
    "rejected": 2,
    "not_selected": 1
  }
}
```

任务终态包括：`completed`、`partial_failed`、`failed`、`cancelled`。

### 5.2 查询任务结果

```http
GET /api/v1/integration/jobs/{job_id}/results?limit=50&offset=0
X-API-Key: <API_KEY>
```

| 查询参数 | 必填 | 默认值 | 限制 |
|---|---:|---|---|
| `limit` | 否 | `50` | 1～100 |
| `offset` | 否 | `0` | 大于等于 0 |
| `decision` | 否 | 无 | 可按单图处理状态筛选 |

查询结果使用 snake_case 字段，并包含 `client_object_key`、`decision`、`original_url`、`enhanced_url`、`ai_tags` 等详细信息。临时下载地址过期后，可重新调用结果接口获取新地址。

正常业务以回调为准，查询接口主要用于回调延迟、下载地址过期和人工排障，不建议高频轮询。

## 6. 兼容与废弃说明

- 客户正式对接使用 `POST /api/v1/integration/jobs` 的 URL JSON 协议；
- `/api/app/image/filter-requests` 暂时接受相同 JSON，建议新系统使用主路径；
- 历史 multipart 文件上传不是当前客户主协议，不要再发送 `-F "filter_profile=..."` 或 `-F "beautify_profile=..."`；
- 客户不应依赖服务端内部对象键或内部处理标准 ID；
- 客户应使用自己的 `objectKey` 关联每张图片，使用 `job_id` 进行任务级排障；
- 响应和回调未来可能增加字段，客户反序列化时应忽略未知字段。

## 8. 联调前双方需要交换的信息

图片服务方向客户提供：

- 联调 Base URL；
- `X-API-Key` 集成密钥；
- 回调 HMAC 签名密钥。

客户方向图片服务方提供：

- 回调地址 `notifyUrl`；
- 回调地址所属域名/IP及网络可达性说明；
- 联调联系人和故障反馈渠道。

# 图片智能处理服务 · 第三方接口联调文档

> 文档版本：2026-08-29  
> 适用范围：客户业务服务对接图片智能处理服务  
> 协议原则：以本文档定义的接口为准，调用方按照本文档调整请求与回调解析。

## 1. 对接说明

图片智能处理采用异步任务模式：

```text
客户业务服务                              图片智能处理服务
     │                                            │
     │── 创建任务并上传图片 ─────────────────────▶│
     │◀── 201 {job_id,status,total} ──────────────│
     │                                            │ Worker 异步处理
     │◀── POST callback_url（完整处理结果）───────│
     │── HTTP 2xx ───────────────────────────────▶│
```

客户创建任务后，无需持续轮询。任务进入终态时，图片服务会主动调用本次请求提交的 `callback_url`。

## 2. 基础信息

| 项目 | 说明 |
|---|---|
| 联调 Base URL | `http://47.111.188.85:18081` |
| 鉴权请求头 | `X-API-Key: <双方约定的密钥>` |
| 创建任务格式 | `multipart/form-data` |
| 回调格式 | `application/json; charset=utf-8` |
| 支持图片 | JPEG、PNG、WebP |
| 单张图片限制 | 不超过 25 MB |
| 单任务图片数 | 1～50 张 |
| 回调超时 | 15 秒 |
| 回调最大投递次数 | 5 次 |

`X-API-Key` 只允许保存在客户服务端，不得放入网页、App、小程序或公开代码仓库。

联调环境可以使用 HTTP；正式公网环境建议使用 HTTPS，避免 API Key、图片和处理结果以明文传输。

## 3. 创建图片处理任务

### 3.1 请求定义

```http
POST /api/v1/integration/jobs
X-API-Key: <API_KEY>
Content-Type: multipart/form-data
```

### 3.2 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `files` | File[] | 是 | 无 | 图片文件；上传多张图片时重复使用同名字段 |
| `callback_url` | String | 是 | 无 | 本次任务的结果回调地址，必须是 HTTP/HTTPS 绝对地址 |
| `filter_enabled` | Boolean | 否 | `true` | v1 保留字段；正式模式只接受 `true` |
| `processing_standards` | String | 是 | 无 | 恰好两个互斥且完整覆盖的过滤标准 ID，以逗号分隔 |
| `filter_profile` | String | 否 | 无 | 旧版字段；正式任务不使用 |
| `unmatched_standard_policy` | String | 否 | `reject` | v1 保留字段；只接受 `reject`，分类异常不会放行 |
| `beautify_enabled` | Boolean | 否 | `true` | v1 保留字段；正式模式只接受 `true` |
| `beautify_profile` | String | 是 | 无 | 独立美化标准 ID |
| `similarity_enabled` | Boolean | 否 | `true` | v1 保留字段；正式模式只接受 `true` |
| `similarity_profile` | String | 否 | `library_similarity_v2` | 相似素材匹配配置 ID |
| `library_scope_node_id` | String | 否 | 无 | 仅在指定标签树根节点及其后代素材中匹配 |
| `enhance_level` | Integer | 否 | `1` | 美化等级，只允许 `0`、`1`、`2` |
| `max_selected` | Integer | 否 | `10` | 本任务最多保留并美化的图片数量，最小为 `1` |

调用方不要手动填写 multipart 的 `boundary`，应由 HTTP 客户端自动生成 `Content-Type`。

### 3.3 curl 示例

```bash
curl -X POST "http://47.111.188.85:18081/api/v1/integration/jobs" \
  -H "X-API-Key: <API_KEY>" \
  -F "files=@product-front.jpg;type=image/jpeg" \
  -F "files=@product-side.png;type=image/png" \
  -F "processing_standards=<条件标准ID1>,<条件标准ID2>" \
  -F "beautify_profile=<美化标准ID>" \
  -F "callback_url=http://<客户服务地址>/v1/callback/ai/theme-image/notify" \
  -F "similarity_profile=library_similarity_v2" \
  -F "enhance_level=1" \
  -F "max_selected=10"
```

## 4. 创建任务同步响应

### 4.1 成功响应

HTTP 状态码：`201 Created`

```json
{
  "job_id": "job_ab1bdc6b2c14480886243bb3e4e25580",
  "status": "queued",
  "total": 2
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `job_id` | String | 是 | 图片服务任务唯一编号，客户必须保存 |
| `status` | String | 是 | 创建成功时通常为 `queued` |
| `total` | Integer | 是 | 本任务包含的图片数量 |

客户应使用 `job_id` 关联后续回调、补偿查询和故障排查。

### 4.2 失败响应

失败响应通常为：

```json
{
  "detail": "错误原因"
}
```

| HTTP 状态码 | 含义 | 客户处理建议 |
|---|---|---|
| `400` | 参数、图片类型、大小、数量或处理标准不合法 | 修正请求后重新提交 |
| `401` | API Key 缺失或错误 | 检查请求头与密钥配置 |
| `413` | 请求体过大 | 减少图片数量或图片大小 |
| `422` | 缺少必填字段或字段类型错误 | 根据 `detail` 修正请求 |
| `429` | 请求过于频繁 | 指数退避后有限重试 |
| `500` | 图片服务内部错误 | 记录请求时间与响应，稍后有限重试 |
| `503` | 服务依赖或集成密钥未配置 | 联系图片服务管理员 |

只有收到 HTTP `201` 且 `job_id` 非空，才表示任务受理成功。

## 5. 处理结果回调

任务进入以下任一终态时，图片服务向创建任务时提交的 `callback_url` 发起一次完整结果回调：

| 状态 | 含义 |
|---|---|
| `completed` | 全部图片处理完成 |
| `partial_failed` | 部分图片失败，其余结果可继续使用 |
| `failed` | 任务失败 |
| `cancelled` | 任务已取消 |

### 5.1 回调请求头

```http
POST {callback_url}
Content-Type: application/json; charset=utf-8
X-Callback-Event: image.job.finished
X-Callback-Id: <event_id>
X-Callback-Timestamp: <Unix 秒时间戳>
X-Callback-Signature: sha256=<HMAC-SHA256 十六进制摘要>
```

当前回调不携带创建任务所用的 `X-API-Key`。服务使用双方约定的回调密钥对 `<timestamp>.<原始请求体字节>` 计算 HMAC-SHA256；客户应校验签名、时间戳有效窗口，并继续按 `event_id` 做幂等处理。客户回调主机必须加入服务端 `CALLBACK_ALLOWED_HOSTS` 白名单。

### 5.3 任务级字段

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `event_id` | String | 是 | 回调幂等键；相同值可能重复投递 |
| `event` | String | 是 | 固定为 `image.job.finished` |
| `job_id` | String | 是 | 创建任务时返回的任务编号 |
| `status` | String | 是 | 任务终态 |
| `completed_at` | DateTime | 是 | ISO 8601 格式完成时间 |
| `total` | Integer | 是 | 图片总数 |
| `selected` | Integer | 是 | 保留数量 |
| `rejected` | Integer | 是 | 因过滤条件被淘汰的数量 |
| `not_selected` | Integer | 是 | 质量合格但未进入优选的数量 |
| `result_total` | Integer | 是 | 回调包含的单图结果总数 |
| `download_expires_in` | Integer | 是 | 临时下载地址有效期，单位为秒 |
| `images` | Array | 是 | 单图结果集合 |
| `error_message` | String/null | 是 | 任务失败、部分失败或取消时的说明 |

### 5.4 单图结果字段

| 参数 | 类型 | 说明 |
|---|---|---|
| `image_id` | String | 图片服务生成的单图编号 |
| `decision` | String | 单图处理决定 |
| `score` | Number/null | 综合质量评分，范围 0～100 |
| `original_object_key` | String | 图片服务内部的原图对象键 |
| `enhanced_object_key` | String/null | 图片服务内部的美化图对象键 |
| `original_url` | String/null | 原图临时下载地址 |
| `enhanced_url` | String/null | 美化图临时下载地址；未美化时为空 |
| `files_expired` | Boolean | 图片文件是否已超过保留期 |
| `reject_codes` | String[] | 结构化淘汰代码 |
| `reasons` | String[] | 处理说明或淘汰原因 |
| `metrics` | Object/null | 原图质量评分 |
| `enhanced_metrics` | Object/null | 美化图质量评分 |
| `ai_tags` | Object/null | AI 摘要、标签、分类、置信度和风险信息 |
| `tagging_result` | Object/null | 相似素材匹配结果 |

`decision` 可能值：

| 值 | 含义 |
|---|---|
| `selected` | 图片已保留 |
| `rejected` | 图片不符合过滤条件，已淘汰 |
| `not_selected` | 图片合格，但未进入优选数量 |
| `failed` | 单图处理失败 |
| `cancelled` | 单图处理被取消 |

`metrics` 和 `enhanced_metrics` 均包含：`sharpness`、`exposure`、`contrast`、`noise`，评分范围为 0～100。

`ai_tags.tags` 才是 AI 标签字符串数组；`ai_tags` 本身是对象，不是字符串数组。

## 6. 客户回调响应要求

客户成功校验并保存回调后，返回任意 HTTP 2xx。例如：

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "code": "200",
  "msg": "success",
  "data": {}
}
```

图片服务只判断 HTTP 状态码，不解析响应体。

- 非 2xx、连接失败或 15 秒内未响应，图片服务会自动重试；
- 默认最多投递 5 次；
- 重试采用指数退避；
- 回调为“至少一次投递”，客户必须按 `event_id` 幂等处理；
- 建议先完成参数校验和持久化并立即返回 2xx，再异步下载图片或执行其他耗时业务。

## 7. 单图归属规则

当前创建接口不接收客户侧 `objectKey`，上传后会生成图片服务内部的随机 `original_object_key`，回调也不会返回客户上传时的原始文件名。

因此，客户不能按照原 `objectKey` 或 `images` 数组顺序关联多图结果。现阶段统一采用以下联调规则：

1. 每个任务只上传一张图片；
2. 客户保存 `job_id → 客户 objectKey` 的映射；
3. 收到回调后，先根据 `job_id` 找到客户图片，再读取 `images[0]` 的处理结果；
4. 不得依赖内部 `original_object_key` 与客户对象键相同。

如果后续需要一个任务上传多张图片并逐图写回，需双方另行确认单图透传标识字段。

## 8. 补偿查询接口

正常流程以回调为准，以下接口只用于回调延迟时的人工排障和补偿。

### 8.1 查询任务进度

```http
GET /api/v1/integration/jobs/{job_id}
X-API-Key: <API_KEY>
```

### 8.2 获取任务结果

```http
GET /api/v1/integration/jobs/{job_id}/results?limit=50&offset=0
X-API-Key: <API_KEY>
```

临时下载地址过期后，可以重新调用结果接口获取新的下载地址。

## 9. 与旧协议的调整对照

以下旧字段和旧地址不再使用：

| 旧协议 | 当前联调协议 |
|---|---|
| `/api/app/image/filter-requests` | `/api/v1/integration/jobs` |
| `application/json` | `multipart/form-data` |
| `notifyUrl` | `callback_url` |
| `images[].imageUrl` | `files` 文件上传 |
| `images[].objectKey` | 当前不接收；通过单图任务及 `job_id` 关联 |
| `taskId` | `job_id` |
| `ok` | 根据 HTTP `201` 判断受理成功 |
| 回调 `results` | 回调 `images` |
| `enhancedUrl` | `enhanced_url` |
| `aiTags` | `ai_tags.tags` |
| `errorMessage` | `error_message` |
| `enhancedMd5` | 当前接口不提供 |

客户不得继续向图片服务发送旧版 JSON 创建报文，否则接口将返回 `400`、`404` 或 `422`。

## 10. 联调验收清单

- [ ] 客户服务端能够使用 multipart 上传图片；
- [ ] 请求头正确携带 `X-API-Key`；
- [ ] 使用服务方提供的有效过滤标准 ID 和美化标准 ID；
- [ ] 创建成功后保存 `job_id`；
- [ ] 联调阶段按照“单任务单图”建立 `job_id → objectKey` 映射；
- [ ] `callback_url` 能从图片服务所在网络访问；
- [ ] 回调接口能在 15 秒内返回 HTTP 2xx；
- [ ] 按 `event_id` 实现幂等；
- [ ] 正确解析 snake_case 字段和 `ai_tags.tags`；
- [ ] 能及时下载 `original_url`、`enhanced_url`；
- [ ] 正式环境启用 HTTPS，API Key 不出现在前端和日志中。

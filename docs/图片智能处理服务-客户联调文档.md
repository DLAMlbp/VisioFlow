# 图片智能处理服务 · 客户联调文档

## 1. 文档说明

本文档用于客户业务服务与图片智能处理服务进行接口联调。

服务采用异步处理模式：客户创建任务后，接口立即返回任务编号；图片处理完成后，服务主动向本次请求传入的回调地址推送结果。

```text
客户服务端                           图片智能处理服务
    │                                       │
    │── POST /api/v1/integration/jobs ─────▶│ 创建异步任务
    │◀── 201 {job_id,status,total} ─────────│
    │                                       │ 图片处理 Worker 异步运行
    │◀── POST callback_url ─────────────────│ 推送终态及完整结果
    │── HTTP 2xx ──────────────────────────▶│ 确认接收成功
```

## 2. 基础信息

| 项目 | 说明 |
|---|---|
| 联调地址 | `http://47.111.188.85:18081` |
| 正式环境 | 建议使用 HTTPS 域名 |
| 请求鉴权 | `X-API-Key: <双方约定的密钥>` |
| 创建任务格式 | `multipart/form-data` |
| 回调格式 | `application/json; charset=utf-8` |
| 支持图片 | JPEG、PNG、WebP |
| 单张限制 | 不超过 25 MB |
| 单任务限制 | 1～50 张 |
| 请求体限制 | 不超过 512 MB |

HTTP 地址可用于内网或受控环境联调；正式公网环境建议使用 HTTPS，避免图片、临时下载地址和处理结果在传输过程中被监听或篡改。

API Key 只能保存在双方服务端，不得写入浏览器、App、小程序或公开代码仓库。

## 3. 创建图片处理任务

### 3.1 请求

```http
POST /api/v1/integration/jobs
X-API-Key: <API_KEY>
Content-Type: multipart/form-data
```

### 3.2 入参

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `files` | File[] | 是 | 无 | 待处理图片；通过多个同名字段上传多张图片 |
| `filter_profile` | String | 是 | 无 | 过滤标准 ID，由服务方提供 |
| `beautify_profile` | String | 是 | 无 | 美化标准 ID，由服务方提供 |
| `callback_url` | String | 是 | 无 | 本次任务结果回调地址，支持 HTTP/HTTPS 绝对地址 |
| `similarity_profile` | String | 否 | `library_similarity_v2` | 相似素材匹配配置 |
| `enhance_level` | Integer | 否 | `1` | 美化等级，可选 `0`、`1`、`2` |
| `max_selected` | Integer | 否 | `10` | 最多保留并美化的图片数量，最小值为 `1` |

### 3.3 curl 示例

```bash
curl -X POST "http://47.111.188.85:18081/api/v1/integration/jobs" \
  -H "X-API-Key: <API_KEY>" \
  -F "files=@living-room.jpg;type=image/jpeg" \
  -F "files=@bedroom.png;type=image/png" \
  -F "filter_profile=<过滤标准ID>" \
  -F "beautify_profile=<美化标准ID>" \
  -F "callback_url=http://<客户服务地址>/v1/callback/ai/theme-image/notify" \
  -F "similarity_profile=library_similarity_v2" \
  -F "enhance_level=1" \
  -F "max_selected=10"
```

请勿手动填写 multipart 的 `boundary`；应由 HTTP 客户端自动生成完整的 `Content-Type` 请求头。

## 4. 创建任务同步响应

### 4.1 成功响应

HTTP 状态码：`201 Created`

```json
{
  "job_id": "job_ab1bdc6b2c14480886243bb3e4e25580",
  "status": "queued",
  "total": 2
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `job_id` | String | 是 | 任务唯一编号，相当于客户系统中的 `taskId` |
| `status` | String | 是 | 创建时通常为 `queued` |
| `total` | Integer | 是 | 本任务图片总数 |

客户应保存 `job_id`，用于关联回调和问题排查。

### 4.2 失败响应

```json
{
  "detail": "错误原因"
}
```

| HTTP 状态码 | 含义 | 处理建议 |
|---|---|---|
| `400` | 参数、图片格式、大小或数量不合法 | 修正请求后重新提交 |
| `401` | API Key 缺失或错误 | 检查服务端密钥配置 |
| `413` | 整个请求体超过 512 MB | 减少图片数量或文件大小 |
| `422` | 缺少必填字段或字段类型不正确 | 根据响应 `detail` 修正字段 |
| `429` | 请求过于频繁 | 指数退避后有限重试 |
| `500` | 服务内部错误 | 记录时间和响应，稍后有限重试 |
| `503` | 服务或集成密钥尚未配置 | 联系服务管理员 |

## 5. 结果回调

任务进入终态后，图片智能处理服务主动调用创建任务时提交的 `callback_url`。

终态包括：

- `completed`：全部处理完成；
- `partial_failed`：部分图片失败，其余结果可用；
- `failed`：任务失败；
- `cancelled`：任务已取消。

### 5.1 回调请求

```http
POST {callback_url}
Content-Type: application/json; charset=utf-8
X-Callback-Event: image.job.finished
X-Callback-Id: <event_id>
```

### 5.2 回调请求体示例

{

    {
      "image_id": "img_xxx",

### 5.3 任务级回调字段

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `event_id` | String | 是 | 回调幂等键；重复收到相同值时不得重复处理 |
| `event` | String | 是 | 固定为 `image.job.finished` |
| `job_id` | String | 是 | 创建任务时返回的任务编号 |
| `status` | String | 是 | 任务终态 |
| `completed_at` | DateTime | 是 | 任务完成时间，ISO 8601 格式 |
| `total` | Integer | 是 | 图片总数 |
| `selected` | Integer | 是 | 保留数量 |
| `rejected` | Integer | 是 | 淘汰数量 |
| `not_selected` | Integer | 是 | 质量合格但未进入优选数量的图片数 |
| `result_total` | Integer | 是 | 本次回调的图片结果总数 |
| `download_expires_in` | Integer | 是 | 临时下载地址有效期，单位为秒 |
| `images` | Array | 是 | 单图处理结果集合 |
| `error_message` | String/null | 是 | 任务失败、部分失败或取消时的任务级说明 |

### 5.4 单图结果字段

| 参数 | 类型 | 说明 |
|---|---|---|
| `image_id` | String | 图片服务生成的单图编号 |
| `decision` | String | 单图处理决定，枚举见下文 |
| `score` | Number/null | 综合质量评分，范围 0～100 |
| `original_object_key` | String | 图片服务内部的原图对象键 |
| `enhanced_object_key` | String/null | 图片服务内部的美化图对象键 |
| `original_url` | String/null | 原图临时下载地址 |
| `enhanced_url` | String/null | 美化图临时下载地址；未美化时为空 |
| `files_expired` | Boolean | 文件是否已超过保留期 |
| `reject_codes` | String[] | 结构化淘汰代码 |
| `reasons` | String[] | 中文处理说明或淘汰原因 |
| `metrics` | Object/null | 原图质量指标 |
| `enhanced_metrics` | Object/null | 美化后的质量指标 |
| `ai_tags` | Object/null | AI 摘要、标签、分类、置信度和风险信息 |
| `tagging_result` | Object/null | 相似素材匹配结果与标签路径 |

`decision` 枚举：

| 值 | 含义 |
|---|---|
| `selected` | 图片已保留 |
| `rejected` | 图片不符合过滤要求，已淘汰 |
| `not_selected` | 图片质量合格，但未进入本任务优选数量 |
| `failed` | 单图处理失败 |
| `cancelled` | 单图处理被取消 |

### 5.5 质量指标字段

`metrics` 和 `enhanced_metrics` 使用相同结构：

| 参数 | 类型 | 说明 |
|---|---|---|
| `sharpness` | Number | 清晰度评分 |
| `exposure` | Number | 曝光评分 |
| `contrast` | Number | 对比度评分 |
| `noise` | Number | 噪点评分 |

### 5.6 AI 标签字段

| 参数 | 类型 | 说明 |
|---|---|---|
| `status` | String | AI 标签处理状态 |
| `summary` | String/null | 图片内容摘要 |
| `tags` | String[] | AI 标签列表 |
| `categories` | Object | 分类结果 |
| `candidate_tags` | String[] | 待复核候选标签 |
| `confidence` | Number/null | 置信度，范围 0～1 |
| `risks` | String[] | 风险提示 |
| `source_object_key` | String/null | AI 分析使用的内部对象键 |
| `error_message` | String/null | AI 标签失败说明 |

### 5.7 相似素材匹配字段

| 参数 | 类型 | 说明 |
|---|---|---|
| `decision` | String | 匹配决定，例如 `matched`、`pending_review`、`unmatched` |
| `tag_path` | String[] | 匹配到的完整标签路径 |
| `matched_asset_id` | String/null | 匹配到的素材编号 |
| `similarity` | Number/null | 图片向量相似度，范围 0～1 |
| `final_score` | Number/null | 综合匹配分，范围 0～1 |
| `message` | String | 匹配结果说明 |

## 6. 客户回调响应

客户收到回调并成功保存结果后，应返回任意 HTTP 2xx。

客户现有响应格式可以继续使用：

```json
{
  "code": "200",
  "msg": "success",
  "data": {}
}
```

图片服务只判断 HTTP 状态码，不解析响应体。

- 回调超时：15 秒；
- 非 2xx、连接失败或超时会自动重试；
- 默认最多投递 5 次；
- 重试采用指数退避；
- 回调属于“至少一次投递”，客户必须按 `event_id` 幂等处理。

建议客户回调接口先完成参数校验和结果持久化，立即返回 HTTP 2xx，再异步执行图片下载、业务通知等耗时操作。

## 7. 单图归属约定

当前接口不接收客户侧 `objectKey`，上传文件会转换为图片服务内部的随机对象键，回调也不会返回客户原始文件名。因此，多图任务不能使用客户原 `objectKey` 直接关联回调结果，也不能依赖 `images` 数组顺序进行归属。

联调阶段建议采用以下方式之一：

1. **单任务单图**：每个 Job 只上传一张图片，客户保存 `job_id → 客户 objectKey` 的映射关系；
2. **扩展透传字段**：如必须一个 Job 上传多张图片并按客户 `objectKey` 回写，需要双方另行确认并增加单图透传标识字段。

在透传字段尚未扩展前，推荐使用“单任务单图”方式进行正式数据写回。

## 8. 补偿查询接口

正常业务流程以回调为准。以下接口保留用于回调延迟时排障和人工补偿。

### 8.1 查询任务进度

```http
GET /api/v1/integration/jobs/{job_id}
X-API-Key: <API_KEY>
```

### 8.2 获取任务结果

```http
GET /api/v1/integration/jobs/{job_id}/results?limit=50&offset=0
X-API-Key: <API_KEY>
```

临时下载地址过期后，可以重新请求结果接口获取新的地址。

## 9. 联调验收清单

- [ ] 客户服务端能够使用 `multipart/form-data` 上传图片；
- [ ] 客户请求头能够正确携带 `X-API-Key`；
- [ ] `filter_profile` 和 `beautify_profile` 使用服务方提供的有效 ID；
- [ ] `callback_url` 能从图片服务所在网络访问；
- [ ] 客户回调接口能在 15 秒内返回 HTTP 2xx；
- [ ] 客户已按 `event_id` 实现幂等；
- [ ] 客户已处理全部任务终态和单图 `decision`；
- [ ] 客户能及时下载 `original_url` 和 `enhanced_url`；
- [ ] 联调阶段已确认单图归属方案；
- [ ] 正式环境已启用 HTTPS，密钥未出现在前端和日志中。
